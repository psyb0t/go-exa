# go-exa

Unofficial Go client for the Exa search API, generated from the OpenAPI spec Exa publishes. If you only want to use the client from an agent, read [.agents/skills/go-exa/SKILL.md](.agents/skills/go-exa/SKILL.md) instead; this file is about changing the code.

## Architecture

One generated package, `exa`, at the module root, driven by `gen.go`:

`scripts/fetch-spec.sh` downloads `exa-openapi-spec.yaml` from the exa-labs/openapi-spec repository to `api/openapi.yaml` → oapi-codegen with `config.yaml` → `client.gen.go`.

## Stack

- Go 1.26.9.
- oapi-codegen, pinned as a `tool` dependency in `go.mod`.
- Runtime: `github.com/oapi-codegen/runtime`.

## Layout

- `gen.go`, `config.yaml`, `client.gen.go`: the package.
- `client_test.go`, `example_test.go`: tests, including the README example.
- `scripts/`: spec download, lint and security scan scripts.
- `api/`: the downloaded spec, gitignored.
- `vendor/`: committed, regenerated by `make dep`.

## Dev workflow

Everything runs in the `Dockerfile.dev` image. You need Docker and Make.

```bash
make dep       # go mod tidy + go mod vendor
make generate  # download the spec and regenerate
make lint      # shellcheck, shfmt, go fix, golangci-lint
make test      # go test -race
make sec       # gitleaks, govulncheck, semgrep
```

## Project-specific landmines

- The spec reuses names for a schema and a response wrapper, so `config.yaml` turns on `resolve-type-name-collisions` and the wrappers get a `2` suffix (`SearchResponse2`). Turning it off breaks the build.
- Several request and response fields are `oneOf` unions (`Answer`, `Context`, `Text`, `Highlights`). oapi-codegen generates `As...` and `From...` methods for them instead of plain fields; examples must use those.
- `make generate` always downloads the current spec, so it can change the client even when nothing here changed. Review the generated diff before committing it.
